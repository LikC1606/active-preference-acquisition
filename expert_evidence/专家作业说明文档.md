# Active Preference Acquisition — 作业说明

## 文件与角色

交付包分为三个目录：

1. `workspace/` 是 Harbor 运行目录。Agent 只能修改
   `workspace/harbor_task/solution/select.py`；题面、评分器、环境和 Starter Code
   均为只读。
2. `expert_evidence/` 保存专家标注、两条 Agent 轨迹和最终
   `best_method/`。这些文件不挂载到 Agent 工作区。
3. `optimization_evidence/` 保存数据指纹、Baseline/Reference 训练、模型重载、
   统计比较和运行收据。这些文件也不挂载到 Agent 工作区。

比较分为两层。Baseline 和 Reference 是算法臂：Baseline 使用未修改的 Starter，
Reference 使用专家提供的 ARM-FI 参考方法。GPT 和 Seed 是两条独立的 Agent 轨迹，
都从 Starter 开始提出候选方法。Agent 轨迹不是算法臂，两个轨迹也不合并统计。

## 运行流程

```text
Starter Code ──► Agent 修改 solution/select.py
              ──► 五个 seed 的 Public/Dev 评分
              ──► 保留当前最佳方法
              ──► 新环境重新评分
              ──► expert_evidence/best_method/
```

Baseline、Reference 和最终 best 使用同一任务评分协议。评分器从源码开始清理缓存、
训练五个 seed 并写入结果，不接受 Agent 自报的分数或模型。

## 任务接口

Task ID 为 `research/active-preference-acquisition`，类型为 S1，研究方向为主动偏好
采样。本包只包含这一道任务，没有任务变体。

唯一优化面是 `solution/select.py:select_pairs`。输入包含 22,500 个候选对的 64 维
特征差、预测 reward 差、`k`、`seed` 和轮次；输出为 500 个不重复索引，并保留索引
顺序。每次调用在新的隔离进程中执行，不保留跨轮状态。

训练数据、候选池生成、标注概率、网络结构、优化器、seed 和评分协议均固定。
Baseline 是随机选择的未修改 Starter，归一化分数固定为 0。Reference 使用论文
ARM-FI 的 D-optimal 规则，仅用于专家侧和平台验收。

## 固定实验协议

数据来自原仓库公开的约 10 GB quickstart 数据。包内只提供预计算 embedding；按
prompt 划分 33,500 个训练样本和 4,188 个 dev 样本，每个 prompt 有十条回答。
Agent 可以读取 embedding，不能读取 reward target。来源、文件指纹和切分规则见
`optimization_evidence/data_manifest.json`。

seed 固定为 101、202、303、404、505。每个 seed 从初始化开始训练 40 轮，累计收集
20,000 labels。第 0 轮使用随机 bootstrap，后续轮次调用 selector。每轮使用累计
标注重新初始化并训练 `2048-64-64-64-1` GELU MLP，输出层无 bias，执行 1,000 次
full-batch Adam update，learning rate 为 0.001；每个 seed 共 40,000 updates。标注
概率为 `sigmoid(reward_a - reward_b)`，不做 reward normalization。

任务使用原始 quickstart 数据和上游 `train_BT` 默认参数。论文没有公开完整实验驱动，
因此本包不包含独立的 500-response test，也不声称复现论文全部实验数值。完整协议和
限制见 `optimization_evidence/experiment_plan.json`。

## 构建与运行

解压 `workspace/`、`expert_evidence/` 和 `optimization_evidence/`，在解压根目录执行：

```sh
docker compose -p arm-acquisition \
  -f workspace/harbor_task/environment/docker-compose.yaml build --no-cache

docker compose -p arm-acquisition \
  -f workspace/harbor_task/environment/docker-compose.yaml up -d --no-build

docker compose -p arm-acquisition \
  -f workspace/harbor_task/environment/docker-compose.yaml \
  exec -T main sh -c 'cd /harbor_task && ./solution/solve.sh --output solution/artifacts/current'
```

`main` 是 Agent 公共环境，`evaluator` 是私有评分环境。依赖从随包 wheels 离线安装。
容器不挂载任务数据、不联网，也不依赖实验室账号或 AcquisitionBroker。离线构建前需
准备公开基础镜像 `python:3.11.11-slim-bookworm`。Harbor 的 Agent 和 separate
verifier 分别使用 `environment/` 与 `tests/` 的 Compose 配置；本地标准验证仍通过
官方环境、产物传输和 Verifier 接口执行。

公共测试入口是 `./tests/test.sh`，顺序为 24 项 contract tests、只读 Baseline
calibration 和 Candidate 完整评分。成功结果写入 `reward.json` 与 `observations.json`。
要重跑 Baseline、Reference 或 best，必须为每个方法创建新的独立评分容器。已有容器会
按 source/protocol hash 复用或续算结果，不能把复用结果当作冷启动预算验收。

前述命令运行未修改的 Starter。重跑 Reference 时，新建独立 project 后复制
Reference；该 project 不运行 Coding Agent：

```sh
docker compose -p arm-reference \
  -f workspace/harbor_task/environment/docker-compose.yaml up -d --no-build

docker compose -p arm-reference \
  -f workspace/harbor_task/environment/docker-compose.yaml \
  cp workspace/reference/select.py main:/harbor_task/solution/select.py

docker compose -p arm-reference \
  -f workspace/harbor_task/environment/docker-compose.yaml \
  exec -T main sh -c 'cd /harbor_task && ./solution/solve.sh --output solution/artifacts/reference'
```

Reference 的完整五个 seed 分数为 `0.2670160049935782`。best 使用另一个新 project，
把复制源换成 `expert_evidence/best_method/select.py`；本次干净五个 seed 的复跑分数为
`0.24927529058448603`。各 seed 的误差见输出目录的 `observations.json`。使用完毕后
对每个 project 执行相同 Compose 文件的 `down`。

已完成模型可以用下面的命令复评：

```sh
python3 -B optimization_evidence/runtime/private/evaluate.py \
  --selector workspace/reference/select.py \
  --output ../reference-replay --cached-only
```

将 `--selector` 换成 `workspace/harbor_task/solution/select.py` 或
`expert_evidence/best_method/select.py` 可检查 Baseline 或 best。该命令只检查模型哈希
和重载记录，不新增训练。模型及重载凭据位于各自的 `runs/seed_*/`；原生训练会重新加载
最终 checkpoint，并要求重算指标与保存前一致。完整操作见
`optimization_evidence/runtime/LOCAL_PACKAGE.md`。

## 评分与统计

原始指标为 `one_minus_spearman`，越小越好。对每个 dev prompt 的十条回答计算模型与
oracle 排序的 Spearman correlation，再用 1 减去 4,188 个 prompt 的均值。最终分数取
五个 seed 最后一轮模型误差的算术平均；`best_of_10` 只作诊断。

| 算法臂 | 平均误差 | 归一化分数 |
| --- | ---: | ---: |
| Baseline B | 0.6799700626090104 | 0 |
| Reference R | 0.4984071729759192 | 0.2670160049935782 |
| 数学下界 U | 0 | 1 |

计算公式为 `score = (B - mean_error) / B`，连续且不裁剪。B 与 R 均来自同一协议下的
五次独立训练，不取单次最好值。Baseline sample standard deviation 为
`0.038293894561585294`，Reference 改善为 `4.741301236443756σ`；五个配对 seed
均改善，达到 3σ，未达到 5σ，仍需平台统计复核。逐次记录见
`optimization_evidence/comparison_summary.json`。

Public/Dev 分数用于专家侧迭代和验收。Baseline 的归一化分数固定为 0，Reference
用于证明题目可解，不是分数上限；正式 Hidden 评测由平台独立执行。论文原始实验数值、
Reference 分数和 Agent 分数属于不同证据，不能互相替代。

## Agent 轨迹

Codex + `gpt-5.6-sol` 独立有效运行 10.835040 小时，完成 6 轮；典型完整单轮耗时
110.149 分钟。Codex + `doubao-seed-2.1-turbo` 独立有效运行 11.304324 小时，完成
7 轮。两路均从 Starter 开始，每路请求并发为 1，最小请求间隔 30 秒，输出上限为
2,048 tokens；每轮从提出改动到评分返回共用 7,200 秒预算，且每次出分均完成五个 seed 的
新训练。

超过两小时单轮目标的旧轨迹保留为 superseded 证据，不计入本次时长和轮次。传输失败和
方法失败同样保留，不改写为成功。最终轨迹只保留 round 和 method_summary。

选中的 GPT 方法分数为 `0.249275290584`，已通过干净环境五个 seed 的复跑。
`best_method/` 保存唯一最终 Agent 代码；历史源码、prompt 和原始模型输出保存在包外
的 operator archive。

## 资源与隔离

每套评分环境使用 8 CPU、36 GiB、0 GPU，不分配 GPU 型号。trainer 使用 6 CPU/32 GiB，
selector 使用 2 CPU/4 GiB，每次最多 60 秒。五个 seed 共用 7,200 秒出分预算，包含评分
锁等待；Verifier 的 7,500 秒包含 contract tests、cached Baseline 和 Candidate。
镜像构建上限为 1,800 秒。Setup、Slurm Job 和 Agent 总预算单独记录，不延长单次
Candidate 的出分预算。

v14 新作业申请 32 logical CPUs，VM 使用 16 个独立 physical cores。Baseline 与 best
同时运行时各占互不重叠的 8 核；Reference 在 Baseline 完成并清理容器后运行。单个
评分环境的资源、数据和科学协议没有改变。旧作业因共享物理核超过两小时而 TIMEOUT，
原始记录保留。

公共镜像不含 Reference、reward targets、专家材料、本机路径或密钥。selector 使用独立
jail，不能访问外部文件、网络、子进程或 SysV IPC。正式 verifier 接收提交源码后固定
哈希，不采用自报分数或 Agent 提供的模型。结果文件先清理再原子提交，失败按类别记录。
